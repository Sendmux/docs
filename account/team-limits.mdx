Sendmux sets team-level limits for resources that can grow quickly. When usage reaches the request threshold, you can go to the related page to request an increase in capacity.

Each Free account can create one active team. Existing teams keep their current resources and approved limits.

## New Free account limits

| Resource                               | Starting limit |
| -------------------------------------- | -------------- |
| Active teams per account               | 1              |
| Domains                                | 1              |
| Mailboxes                              | 1              |
| Your own or connected sending accounts | 1              |
| Webhooks                               | 1              |
| Credentials                            | 2              |
| Team members                           | Owner only     |

<Note>
  Credentials include manual API keys across all key types and connected apps.
  Pending mailbox credential creation can also reserve capacity until it
  finishes. The **API Keys** page shows both credential classes in that total.
</Note>

## Request an increase

When a resource reaches **80%** of its current limit, Sendmux shows **Request increase** near the usage text on that page. API clients can request more sending-account capacity with `POST /providers/limits/sending-accounts/request-increase`.

Each team and each resource can have one pending request at a time. Requests should be submitted only once. Sendmux emails the requester when the request is approved or denied. Increases, once approved, take effect immediately.

## At the hard limit

Creation is blocked when your usage hits the full limit until you either raise the limit, or delete an existing resource.

API creation requests generate `409 limit_exceeded`. This error cannot be retried unless the capacity is adjusted.

## Email volume

Sendmux does not create a new volume cap for all sending routes as a whole. Your configured providers can still enforce their own limits.

The managed Amazon SES account starts with a limit of 2 accepted recipients per hour and 50 per UTC day. Please request a review from **Accounts** when usage reaches 80% of the daily limit.
