Billing is scoped to each team. Sendmux uses the team balance for billable email and storage usage, then records purchases, usage, auto top-ups, refunds, and adjustments as transactions.

## Usage rates

Sendmux charges each billable event individually. The per-1,000 column is only an equivalent rate for comparison; you do not buy or consume email in blocks of 1,000.

| Activity                                             | Billing unit                           | Rate per unit | Equivalent per 1,000 |
| ---------------------------------------------------- | -------------------------------------- | ------------- | -------------------- |
| Outgoing mail through your own or connected provider | Provider-accepted recipient occurrence | \$0.000150    | \$0.15               |
| Outgoing mail through managed Amazon SES             | Provider-accepted recipient occurrence | \$0.000250    | \$0.25               |
| Inbound mail                                         | Distinct mailbox delivery              | \$0.000150    | \$0.15               |
| Mailbox storage                                      | Decimal GB-month                       | \$0.02        | Not applicable       |

For outgoing mail, each provider-accepted To, CC, or BCC recipient occurrence is billed. Addresses rejected before provider acceptance are not charged.

If the same address appears in more than one recipient field, each provider-accepted occurrence is billed separately.

If a provider's result is unknown, Sendmux keeps the reservation on hold for up to 24 hours while it reconciles the send. The hold is not a usage charge and cannot start an auto top-up by itself. If no result arrives, Sendmux releases the hold.

Inbound usage is counted for each distinct mailbox that receives the message. One message delivered to two mailboxes counts as two deliveries. Mail rejected by mailbox allow or block rules is not billed.

Storage is measured from mailbox usage and prorated by calendar day. One decimal GB is 1,000,000,000 bytes.

Usage transactions can be grouped, so the transaction table may show one **Incoming email usage** line for several received messages in a short period.

## Balance

The Billing page shows current balance, purchased amount over the last 30 days, and consumed amount over the last 30 days.

Every new team is credited with \$1. If your balance is insufficient, sending requests may fail with `insufficient_credits`. Top up before retrying.

## Manual top-up

Select an amount and finish the checkout process. The supported amounts are:

```text
$10, $20, $50, $100, $250, $500, $1,000, $2,500, $5,000
```

The balance updates after the purchase completes.

## Auto top-up

Auto top-up adds balance when your team drops below a threshold.

| Setting           | Options                                                          |
| ----------------- | ---------------------------------------------------------------- |
| Balance threshold | \$1, \$5, \$10, \$25, \$50, \$100, \$200, \$500                  |
| Top-up amount     | \$10, \$20, \$50, \$100, \$200, \$500, \$1,000, \$2,000          |
| Monthly limit     | \$10, \$25, \$50, \$100, \$250, \$500, \$1,000, \$2,000, \$5,000, \$10,000 |

Use a monthly limit that covers expected usage but still caps unexpected spend.

## Low-balance alerts

Low-balance alerts email you when team balance drops below the selected threshold.

```text
$5, $10, $25, $50, $100, $250
```

Alerts are sent at most once every 24 hours for the same team and user.

## Transactions

The transaction table shows balance movements with type, amount, date, and description. Use it to reconcile purchases, auto top-ups, usage, refunds, and manual adjustments.
