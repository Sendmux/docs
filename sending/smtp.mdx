Use SMTP when an existing application, plugin, or mail client already supports SMTP delivery.

<Info>
  The SMTP password is your `smx_mbx_` send-only key, mailbox password, or owner-approved Sending-resource `smx_agent_` token.
  Routing still follows that key or mailbox scope.
</Info>

<SharedSesPolicy />

## Connection details

| Setting | Value |
| --- | --- |
| **Host** | `smtp.sendmux.ai` |
| **Port** | `587` with STARTTLS, or `2525` with STARTTLS |
| **Username** | Any value, such as `smtpuser` |
| **Password** | Your `smx_mbx_` send-only key, mailbox password, or owner-approved Sending-resource `smx_agent_` token |
| **Authentication** | `LOGIN` or `PLAIN` |

## Test with swaks

```bash
swaks --to user@example.com \
  --from hello@example.com \
  --server smtp.sendmux.ai:587 \
  --auth LOGIN \
  --auth-user smtpuser \
  --auth-password "smx_mbx_your_key_here" \
  --tls \
  --header "Subject: Test email" \
  --body "Hello from Sendmux"
```

## Select delivery groups

Add one `X-Sendmux-Delivery-Group` header containing comma-separated group public IDs:

```text
X-Sendmux-Delivery-Group: dgrp_group_a, dgrp_group_b
```

Replace the example IDs with your groups' public IDs. Sendmux trims surrounding whitespace and deduplicates IDs, with a maximum of 50 groups. Empty entries and repeated occurrences of the header are rejected, including when separate occurrences contain the same value. A folded continuation belongs to the same header.

The hint can only narrow the credential's authorised providers. Shared-domain sending ignores it and retains its forced route. See [Delivery groups](/sending/accounts/delivery-groups#restrict-one-message) for the scope rules.

Invalid, unknown, foreign-team, or disallowed hints receive a permanent `550` response. Temporary service failures remain retryable. Sendmux removes the routing header before delivery.

Use [template variables](/sending/template-variables) in subjects and bodies to insert values from the selected account.

## SMTP vs HTTP

| Need | Use |
| --- | --- |
| Existing SMTP-only tool | SMTP |
| New application integration | HTTP API |
| Batch sending | HTTP API |
| Built-in retry protection | HTTP API |
| Native MIME message handling | SMTP |

## What happens next

Successful SMTP sends appear in **Logs** like HTTP sends. Use the message ID, sender, recipient, status, provider, and timestamp to trace delivery.

## Free daily limit

Free teams can send to 50 accepted recipients per UTC day across SMTP and HTTP. Sendmux reserves capacity before returning `250`, so concurrent SMTP sessions cannot cross the cap.

When no daily capacity remains, SMTP returns `550 5.7.1 Daily sending limit reached. Upgrade to Pro to continue.` The message is not queued. Retry after `00:00 UTC` or upgrade the team to Pro.
